# Spec Delta

## Purpose

Правила проверки файлов определяют пригодность каждого материала, комплектность записи и единый итоговый статус для всего загруженного набора.

## ADDED Requirements

### Requirement: Проверка расширения и размера
Система SHALL разрешать расширения PDF, DOCX, XLSX, JPG и PNG без учёта регистра. Недопустимое расширение, нулевой размер и размер файла строго более 20 МБ SHALL давать отдельные замечания уровня `warning`; такой файл SHALL присутствовать в `documents`, но не участвовать в распознавании типа и комплектности. Проверка расширения SHALL предшествовать распознаванию имени.

#### Scenario: Недопустимое расширение
- **WHEN** загружен `дневник_наблюдений.exe`
- **THEN** для файла создаётся `warning` о формате, его `detected_type` пуст и категория дневника остаётся незакрытой

#### Scenario: Граница размера
- **WHEN** файл допустимого расширения имеет размер ровно 20 МБ
- **THEN** он проходит проверку размера

#### Scenario: Превышение размера
- **WHEN** файл допустимого расширения имеет размер более 20 МБ
- **THEN** для него создаётся `warning`, а его категория не засчитывается в комплектности

#### Scenario: Пустой файл обязательной категории
- **WHEN** файл `обратная_связь_родителя.docx` имеет размер 0 байт в дневном комплекте
- **THEN** для него создаётся `warning` о пустом файле, `detected_type` пуст, а отсутствие обратной связи даёт `error` и статус `incomplete`

#### Scenario: Пустой дополнительный файл
- **WHEN** к полному дневному комплекту добавлен пустой `scan_0041.jpg`
- **THEN** результат остаётся `complete` с одним `warning` о пустом файле

### Requirement: Распознавание типа по имени
Система SHALL распознавать категории `observation_diary`, `lesson_report`, `parent_feedback`, `specialist_conclusion` по словосочетаниям «дневник наблюдений», «отчёт о занятии», «обратная связь родителя», «заключение специалиста». Регистр букв и разделители пробел, `_`, `-` между словами SHALL не влиять на результат. Неузнаваемое имя допустимого файла SHALL давать `warning` и пустой `detected_type`.

#### Scenario: Разные написания
- **WHEN** имена файлов содержат `ДНЕВНИК-НАБЛЮДЕНИЙ`, `отчёт_о_занятии`, `обратная связь родителя` и `заключение-специалиста`
- **THEN** все четыре категории распознаются корректно

#### Scenario: Неизвестное имя
- **WHEN** загружен пригодный `scan_0041.jpg`
- **THEN** создаётся `warning` о нераспознанном типе, `detected_type` пуст и файл не закрывает обязательную категорию

### Requirement: Комплектность и итоговый статус
Для `daily` система SHALL требовать дневник наблюдений, отчёт о занятии и обратную связь родителя; для `weekly` дополнительно заключение специалиста. Отсутствие каждой обязательной категории SHALL давать `error`. Дубликат категории SHALL не заменять другую категорию. После обработки всех файлов система SHALL присваивать `incomplete`, если есть хотя бы один `error`, иначе `complete`; одни предупреждения SHALL не делать запись неполной.

#### Scenario: Полный дневной набор
- **WHEN** `daily` содержит три пригодных файла обязательных категорий
- **THEN** статус `complete` и ошибок нет

#### Scenario: Полный недельный набор
- **WHEN** `weekly` содержит четыре пригодных файла обязательных категорий
- **THEN** статус `complete` и ошибок нет

#### Scenario: Недостающая категория
- **WHEN** `daily` содержит дневник и отчёт, но не содержит обратную связь родителя
- **THEN** выдаётся `error` об отсутствии обратной связи и статус `incomplete`

#### Scenario: Дубликат
- **WHEN** `daily` содержит два дневника и один отчёт
- **THEN** отсутствие обратной связи остаётся ошибкой и статус равен `incomplete`

#### Scenario: Предупреждение при полном наборе
- **WHEN** `daily` содержит все обязательные категории и дополнительный `scan_0041.jpg`
- **THEN** статус `complete`, а для дополнительного файла есть `warning`

#### Scenario: Смешанный набор
- **WHEN** `weekly` содержит три пригодные обязательные категории и файл `заключение_специалиста.exe`
- **THEN** есть `warning` о формате, `error` об отсутствующем заключении и статус `incomplete`

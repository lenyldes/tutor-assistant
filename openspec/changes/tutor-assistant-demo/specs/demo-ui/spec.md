# Spec Delta

## Purpose

Публичная страница демонстрирует проверяющему все основные сценарии тестового задания и фактическое взаимодействие с тем же REST API.

## ADDED Requirements

### Requirement: Доступная демонстрационная страница
Система SHALL отдавать из того же сервиса одну страницу без авторизации, содержащую выбор `daily`/`weekly`, ручную загрузку файлов, запуск проверки, историю и просмотр полного результата. Страница SHALL показывать предупреждение «Демо публичное. Не загружайте персональные данные детей».

#### Scenario: Ручная проверка
- **WHEN** посетитель выбирает тип записи, добавляет файлы и запускает проверку
- **THEN** страница вызывает `POST /api/checks` и показывает статус, замечания и сведения о файлах из ответа

#### Scenario: История и детали
- **WHEN** посетитель открывает историю и выбирает проверку
- **THEN** страница показывает список из `GET /api/checks` и полный сохранённый результат из `GET /api/checks/{id}`

### Requirement: Готовые сценарии
Страница SHALL предоставлять кнопки «полный daily», «полный weekly», «неполный комплект» и «нераспознанное имя». Они SHALL формировать запросы из синтетических файлов без персональных данных; ручная загрузка SHALL оставаться доступной.

#### Scenario: Полный набор с неизвестным файлом
- **WHEN** посетитель запускает готовый сценарий «нераспознанное имя»
- **THEN** запрос содержит полный обязательный комплект и дополнительный файл с неизвестным именем, а результат имеет статус `complete` с предупреждением

### Requirement: Прозрачность обращения к API
Страница SHALL показывать для последнего действия метод, путь, тип записи и имена отправленных файлов, рядом HTTP-статус и фактический JSON-ответ. Бинарные части multipart SHALL не отображаться.

#### Scenario: Отправка набора
- **WHEN** посетитель запускает проверку
- **THEN** блок запроса и ответа показывает `POST /api/checks`, тип записи, имена файлов, HTTP-статус и полученный JSON без байтов файлов

# Контрольные примеры

Для всех примеров имена указывают multipart-поле `files`; `record_type` — отдельное поле. Каждый неоговорённый файл имеет размер 1 КБ и допустимые реальные синтетические байты своего формата. Проверяется итоговый статус и уровни замечаний; `check_id` и время меняются от запуска к запуску.

| № | `record_type` и имена файлов | Ожидаемый результат |
| --- | --- | --- |
| 1 | `daily`: `дневник_наблюдений.xlsx`, `отчёт_о_занятии.pdf`, `обратная_связь_родителя.docx` | HTTP 200, `complete`, 3 документа, нет замечаний |
| 2 | `weekly`: файлы №1 + `заключение_специалиста.png` | HTTP 200, `complete`, 4 документа, нет замечаний |
| 3 | `daily`: первые два файла №1 | HTTP 200, `incomplete`, 2 документа, один `error` об обратной связи |
| 4 | `daily`: файлы №1 + `scan_0041.jpg` | HTTP 200, `complete`, 4 документа, один `warning` о неизвестном имени, `detected_type: null` у `scan_0041.jpg` |
| 5 | `weekly`: первые три файла №1 + `заключение_специалиста.exe` | HTTP 200, `incomplete`, 4 документа, `warning` о формате и `error` о заключении; `detected_type: null` у `.exe` |
| 6 | `daily`: файлы №1, но `дневник_наблюдений.xlsx` имеет размер 20 МБ + 1 байт | HTTP 200, `incomplete`, 3 документа, `warning` о размере и `error` о дневнике |
| 7 | `daily`: файлы №1, `дневник_наблюдений.xlsx` имеет размер ровно 20 МБ | HTTP 200, `complete`, 3 документа, нет предупреждения о размере |
| 8 | `daily`: `дневник_наблюдений.xlsx`, `ДНЕВНИК-НАБЛЮДЕНИЙ.pdf`, `отчёт_о_занятии.pdf` | HTTP 200, `incomplete`, 3 документа, `error` об обратной связи; два дневника не заменяют её |
| 9 | `daily`, без поля `files` | HTTP 400, запись в БД не создаётся |
| 10 | `monthly`, с файлом №1 | HTTP 422, запись в БД не создаётся |

После каждого успешного POST `GET /api/checks/{id}` должен вернуть тот же сохранённый результат, а `GET /api/checks` — одну новую строку с количеством всех загруженных файлов, включая непригодные. Для неизвестного `id` ожидается HTTP 404. Во всех результатах `extracted` — `{}`.

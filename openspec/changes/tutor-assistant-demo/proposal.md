# Proposal

## Why

Тестовое задание требует проверять комплект дневных и недельных записей через REST API и сохранять историю в PostgreSQL. Небольшая демонстрационная страница позволит проверяющему увидеть те же сценарии без подготовки multipart-запросов.

## What Changes

- Создать `POST /api/checks`, `GET /api/checks` и `GET /api/checks/{id}` с валидацией запроса, синхронной проверкой и сохранением результатов и метаданных файлов.
- Проверять расширение, размер, узнаваемость имени и комплектность для `daily` и `weekly`; возвращать предупреждения и ошибки с итоговым статусом.
- Отдавать из FastAPI одну статическую страницу с ручной загрузкой, готовыми сценариями, историей, детальным результатом и блоком фактического запроса/ответа.
- Подготовить синтетические демонстрационные файлы, запуск через Docker Compose с PostgreSQL, миграции Alembic, автоматические проверки, инструкцию для запуска и развёртывания на личном сервере.

## Capabilities

### New Capabilities

- `checks-api`: контракт создания проверки, истории, деталей и сохраняемых данных.
- `material-validation`: правила обработки отдельных файлов, комплектности и итогового статуса.
- `demo-ui`: публичная демонстрационная страница и готовые сценарии.

### Modified Capabilities

Нет: существующих спецификаций нет.

## Impact

Новые Python-модули FastAPI, SQLAlchemy и Alembic, тесты pytest, статические файлы в `web/`, PostgreSQL, Dockerfile, `docker-compose.yml`, `.env.example`, демонстрационные файлы и клиентский `README.md`. Содержимое загруженных файлов обрабатывается во время запроса и долговременно не хранится; поле `extracted` возвращается пустым объектом.

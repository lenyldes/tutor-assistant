# Локальная разработка

Требуются Docker с Compose и, для запуска Python на хосте, Python 3.11.

## Контейнеры

Для запуска готового сервиса:

```bash
docker compose up --build
```

Копировать `.env.example` не требуется: Compose использует значения по умолчанию.
Приложение будет доступно на `http://localhost:8000`; перед запуском API
контейнер выполнит `alembic upgrade head`. Данные PostgreSQL сохраняются в
именованном томе `postgres_data`.

При необходимости скопировать `.env.example` в `.env` и поменять порт,
пользователя, пароль или имя БД. При изменении реквизитов БД нужно также
обновить `DATABASE_URL`. Для существующего тома изменение реквизитов
PostgreSQL не меняет уже созданного пользователя и базы; нужен новый том или
ручное изменение в БД. Значения по умолчанию предназначены только для
локальной разработки; при публикации необходимо задать свой пароль.

## Обязательные проверки

```bash
bash scripts/check.sh
```

Сценарий создаёт отдельный Compose-проект с тестовой PostgreSQL, проверяет
Ruff и лимит размера файлов, применяет миграции и запускает pytest. После
проверки тестовые контейнеры и том удаляются, рабочий стенд не затрагивается.

## Python на хосте

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

Перед локальным запуском Python или Alembic заменить в `.env` адрес `db:5432`
на `localhost:5432` (либо на значение `POSTGRES_PORT`). Адрес `db` работает
только внутри сети Compose. `APP_ENV` задаёт режим приложения, `PORT` —
внешний порт API, `POSTGRES_PORT` — внешний порт PostgreSQL.

Затем поднять только PostgreSQL и запустить приложение из активированного
виртуального окружения:

```bash
docker compose up -d db
alembic upgrade head
uvicorn app.main:app --reload --port 8000
```

Локальная БД и приложение должны использовать одинаковые реквизиты. Если
порт `8000` изменён в `.env`, передайте такое же значение флагу `--port`.

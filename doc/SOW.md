## Бизнес-кейс: цифровой помощник тьютора с AI-анализом наблюдений за детьми

- **Проект**: AI-агент для сбора, структурирования и анализа ежедневных наблюдений за детьми с ОВЗ с визуализацией динамики и формированием прозрачных AI-подсказок для команды сопровождения.
- **Проблема**: разрозненные записи наблюдений (Excel, заметки), отсутствие единого профиля ребёнка, ручная обработка данных, сложность выявления закономерностей, отсутствие наглядной динамики для родителей и врачей, нет прозрачности AI-выводов.

### Как процесс работает сейчас (AS IS)

Тьютор ежедневно фиксирует наблюдения (эмоции, коммуникация, поведение, приём пищи, сенсорные реакции, сон) в разрозненных записях. Специалист после занятий заполняет отчёт о занятии отдельно. Родители получают устные отчёты, врачи не имеют доступа к систематизированным данным.

Материалы дня хранятся где придётся — в Excel-таблицах, заметках, сканах и фото на телефоне. Единого идентификатора записи нет, версионности нет, комплектность никто не проверяет. При большом объёме информации сложно увидеть динамику, выявить повторяющиеся связи (например: недосып → агрессия) и вовремя скорректировать ИОМ.

### Как процесс должен работать (TO BE)

- Тьютор вносит наблюдения и прикладывает материалы дня через веб-интерфейс или мобильное приложение по единому шаблону.
- Бэкенд сохраняет материалы в хранилище (файловое/БД), присваивает уникальный ID записи и каждой сущности (дневник наблюдений, отчёт о занятии), фиксирует метаданные (дата, автор, ребёнок).
- Система валидирует комплектность дневной записи: наличие обязательных материалов, форматы, целостность.
- Бэкенд предоставляет API для фронтенда и AI-модулей.
- AI-модуль осуществляет следующие функции: загрузка/получение материалов, запуск проверки записи, получение статуса проверки и отчёта.
- Реализуется версионность: при повторной загрузке записи за ту же дату создаётся новая версия, сохраняется история изменений.
- Обеспечивается безопасность: разграничение прав доступа (тьютор, координатор, родитель, специалист), ребёнок идентифицируется обезличенным кодом.

## Ключевые сценарии использования (User Stories)

- **Как тьютор**, я хочу загрузить дневную запись наблюдений в систему, чтобы бэкенд сохранил её в защищённом хранилище и вернул мне уникальный идентификатор записи.
- **Как координатор сопровождения**, я хочу видеть историю изменений по каждой записи, чтобы контролировать корректность данных.
- **Как разработчик AI-модуля**, я хочу получить через API список материалов записи и их содержимое для извлечения показателей.

## Тестовое задание

**Задача**: реализовать REST API сервис проверки дневных записей наблюдений с сохранением истории в PostgreSQL.

### Требования к API и логике проверок

- Реализовать эндпоинт `POST /api/checks`: принимает файлы (`multipart/form-data`) и тип записи (`daily` / `weekly`), запускает проверку, возвращает результат и сохраняет его в БД.
- Реализовать `GET /api/checks` — список всех проверок (`id`, дата, тип записи, статус, количество материалов).
- Реализовать `GET /api/checks/{id}` — полный результат конкретной проверки.
- Определять тип материала по имени файла (дневник наблюдений, отчёт о занятии, обратная связь родителя, заключение специалиста) и проверять комплектность записи: для `daily` обязательны дневник наблюдений, отчёт о занятии, обратная связь родителя; для `weekly` — все четыре, включая заключение специалиста. Анализ по количеству и по паттерну имени.
- Добавить проверки: недопустимый формат файла (только PDF, DOCX, XLSX, JPG, PNG), размер файла более 20 МБ, нераспознанное имя файла — предупреждение уровня warning.
- Итоговый статус: `complete` (нет нарушений), `incomplete` (есть хотя бы одна ошибка), `check_in_progress`.
- Покрыть тестами через `pytest` логику определения типа материала и формирования итогового статуса — минимум 5 тест-кейсов.
- Весь проект должен подниматься одной командой `docker compose up` — предоставь `Dockerfile` для сервиса и `docker-compose.yml` с сервисом PostgreSQL.
- Репозиторий должен содержать `README.md`: как запустить, как запустить тесты, описание переменных окружения из `.env.example`.
